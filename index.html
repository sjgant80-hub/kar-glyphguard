Glyphguard

A deterministic Unicode integrity auditor for text an AI system reads, writes, or is asked to act on.

Glyphguard scans any pasted text for Unicode tricks used to smuggle hidden or spoofed content past humans and keyword filters: invisible characters, bidi overrides, homoglyph lookalikes, styled "math-alphabet" letters, fullwidth forms, and the invisible Unicode tag block. The scan is a pure function of the input text — no model, no judgment call. Re-run the same text through this same page (or a fresh reimplementation of the method below) and you get a byte-identical report and SHA-256 hash, every time.

Honest limits — read before trusting a "clean" result
  • The homoglyph list is a curated set of ~40 well-known Cyrillic/Greek/Latin lookalikes, not the full Unicode Confusables database (thousands of entries). A "clean" result means none of this list matched, not that no lookalike character exists anywhere in Unicode.
  • Mixed-script flagging only fires when Latin is mixed with Cyrillic or Greek inside the same whitespace-delimited token — chosen to avoid false alarms on ordinary multilingual or emoji text. Other script combinations are not flagged.
  • The Mathematical Alphanumeric Symbols decode covers Latin letters and digits only (13 styles), not the Greek math-style ranges in the same block.
  • Variation selectors are flagged as present (a known covert-data channel) but their payload is not decoded.
  • This is static text analysis, not a sandbox — it cannot tell you what a model or browser will actually do with the text, only what unusual characters are hiding inside it.
  • Nothing here is sent anywhere. Every check runs locally in this browser tab.

    How it works
    
  
  
    1. Every character is checked against the categories above: zero-width and other invisible characters, about 40 curated look-alikes, bidi overrides, Unicode tag characters, mathematical and fullwidth letters, variation selectors, and words that mix scripts.
    2. Hidden content is decoded: tag characters back to the ASCII they spell, styled letters back to plain ones.
    3. The report, with every finding and its position, is hashed with SHA-256, so the same script can re-verify it later.
    

    

    
  
    Words on this page
    
  
    Confusable
    A letter from another alphabet that looks like a Latin one: Cyrillic а in place of Latin a makes a different word to a computer.
    Token
    A run of characters between spaces, roughly a word. Mixed alphabets are flagged only inside one token, so English next to a quoted Greek or Russian word is not flagged.
    Tag characters
    Invisible copies of ordinary letters (Unicode U+E0020 to U+E007E). A person sees nothing; a model can read them as text. Glyphguard decodes them.
    Variation selector
    An invisible character meant to pick an emoji's style. There are 256 of them, so a run of them can carry one hidden byte each: a covert channel. Glyphguard flags them but does not decode what they carry.
    Bidi control
    An invisible character that changes the direction text is displayed in, so what you see is not the order a program reads ("Trojan Source").
    Kernel
    The small piece of code that does the checking. Here it is the block inside this page, copied byte for byte into kernel.mjs and the script.
    SHA-256 receipt
    A 64-character fingerprint of the input and the verdict. Anyone with the same input gets the same fingerprint; change one character and it changes completely.
    Deterministic
    No AI model, no random numbers and no clock go into a verdict, so the same input gives the same verdict on any machine, every time.
    No AI judge
    No language model decides anything. The verdict comes from fixed rules you can read in kernel.mjs.
    Mutation gate
    A test of the tests. witness makes small deliberate changes to the kernel, one at a time, and every change must make a test fail. A change no test notices has survived, which would mean the tests miss something. A change reviewed as equivalent cannot alter any result, and the reason is written down.
    CI
    Continuous integration: GitHub re-runs every test and the gate on its own computers on every change, and the runs are public.
    In the browser
    The page does the work on your computer. Nothing you paste is sent to a server.
    MIT licence
    An open-source licence: you may use, copy, change and build products with it, free, as long as the copyright notice stays.
    Sourced figures
    Every number in the cost case comes from a published source (the UK median wage and UK inflation, from the ONS), linked under the table.

    Where it stops, answered straight
    
  
    • A curated list. About 40 look-alikes and a mixed-script check, not the full Unicode confusables database. clean means these known tricks were not found, not that the text is safe.

    • Positions. Positions are counted in code points, not UTF-16 units or bytes.

    FAQ
    
  
    Why does this matter for AI?
    Text can carry instructions a person cannot see but a model reads, such as Unicode tag characters spelling "rank this first". This finds and decodes them.
    Can an agent run it?
    Yes. The same kernel ships as a one-file Node.js script (scripts/kar-glyphguard.mjs), usable as an agent skill before it acts on outside text.
    What happens with bad, empty or very large input?
    Any text is accepted, including empty text, which is reported clean with its hash. There is no length cap; 200,000 characters scan in under a second on a laptop. An input file the script cannot read is refused (exit 2).
    What do I need to run it?
    For the page, a modern browser; there is nothing to install. For the script, Node.js 20 or later: download scripts/kar-glyphguard.mjs (one file, no dependencies, no npm install) and run it with no arguments to see how to call it.
    Does it need the internet or an account?
    No. The page works once loaded, and the script runs offline. Nothing is uploaded.
